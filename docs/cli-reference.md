# CLI reference

The command surface is `process`, `preview`, `server-info`, `help`, and `about`; no arguments launch the interactive menu.

Before the main menu, the application displays welcome and getting-started content from the deployed `Content/application-preamble.md` file. The file is read on every launch, so its wording can be updated without rebuilding. If it is missing or unreadable, the application displays a short fallback directing the operator to `carrot-cli help getting-started` and continues to the menu.

The main menu provides Process Documents, Preview Request, Server Information, iSearch, Help, About, and Exit. The interactive application **Search Summary** identifies the current context and provides cancellation guidance in a two-column layout. Preview Request retains its pending Execute action. Interactive Server Information retains Execute, Help, and Back to Main Menu; Execute prompts for a nonpersisted endpoint and displays `/list` configuration. iSearch validates User Secrets credentials, checks `/health`, discovers live databases, then offers **Select Return Dataset** immediately beneath **Select Database**. That picker lists the configured `iSearchReturnTypes.Results` return-type child names; **Submit Query** remains unavailable until both selections are made and sends the selected group's ordered fields as `fl`. Each result report shows shared total/current/result-page cardinality and retains the iSearch cursor. Its **Search Summary** identifies the live dataset, return dataset, **Data Page**, **Display Page**, current/loaded/total record counts, and the actual loaded-record progress bar. **Next Display Page** is local terminal navigation; **Fetch Next Result Page** performs one cursor-based request; **Fetch All Pages**, immediately below it, performs sequential cursor requests for every remaining page of the same database, query, return dataset, fields, and row limit. Both actions use the documented authenticated one-second request interval and bounded retry behavior. **Save iSearch Results to Excel** writes every walked page in service order without fetching more data. The workbook uses `ResultPage`, `ResultOrdinal`, configured fields, observed extra fields, and a `Value` column for scalar/array records; duplicate rows are preserved. Empty data is page `0` of `0` and 100% loaded; failed or canceled walks retain their accepted pages and report actual partial progress. iSearch also offers **View Fields** for the selected live database through authenticated `GET /fields/{dataset}`. Field discovery displays the live `name`, `displayName`, `fieldType`, `defaultQueryField`, `defaultResultField`, `multiValued`, and `searchOnly` metadata columns with paging; returning to the submenu retains compatible selections. Once records are loaded, **Categorize iSearch Results** submits exactly `nihApplId`, `title`, `abstract`, and `specificAims` to Carrot, normalizing missing, numeric, or null scalar values to Carrot-compatible strings while retaining original values for categorized export, then offers categorized paging and **Save Categorized iSearch Results to Excel**.

Process Documents provides an editable ordered input list. Add Path accepts one individual supported file, folder, or ZIP archive and removes matching surrounding single or double quotes. Paths are normalized to absolute paths, so both quoted paths with spaces and relative paths are supported. Wildcards, environment-variable expansion, and multiple pasted paths in one prompt are not expanded.

Prepare Documents optionally enables recursion for every folder, discovers and deduplicates sources, safely expands ZIPs, extracts searchable text, hashes successful documents, and retains failures for review. Inputs follow entered order; documents within a folder or archive follow normalized relative-path order. Duplicate canonical sources keep their first occurrence.

Prepared results display five rows per page with status, source, type, size, extracted character count, a 120-character normalized content preview, and failure text. Next/Previous navigate pages; Next is the default whenever another page exists, and Escape returns to retained Batch Actions. Preview JSON Package serializes the exact indented `/cluster` body using the configured default language and algorithm and every ready document's complete title/content. Its display adapts to terminal dimensions, pages the pretty-printed lines, and marks visually wrapped long-string continuations with `↪` without changing the JSON value. JSON paging uses the same forward-default and Escape behavior. Local source metadata is excluded, and the preview neither contacts Carrot nor writes a file.

Process Prepared Items prompts for an absolute HTTP/HTTPS service URL ending exactly in `/service`; `http://localhost:8080/service` is the nonpersisted default. The shared clustering resolver applies the interactive `Lingo` and `English` defaults, then the reusable validator requires those exact identifiers together in `/list`. It sends the same preview-factory request to `/cluster` with JSON request and response negotiation. The interactive request omits `template`, `indent`, and parameters. Every ready document's complete extracted title and text is sent in one request. Redirects are disabled, documented error type/message values are displayed without stack traces, and up to two retries apply only to transport errors, 408, 429, and server failures within a single 120-second operation budget.

A complete success opens Processed Results automatically and adds View Processed Results plus Save Processed Results to Excel to Batch Actions. Five documents appear per page with the submitted index, source/title, assignment status, membership count, nested category paths, and unrounded scores. Every processed-results page also offers Save Processed Results to Excel; Next Page remains selected by default while moving forward, and Save is selected by default on the final page. Saving returns to the same result page. Memberships may overlap; nested nodes use ` > ` between path levels and multiple labels in one node use ` | `. Empty cluster results are valid and explicitly show every document as unassigned. A negative or out-of-range server index rejects the entire response. Failed reprocessing retains the prepared batch and latest successful result. Processing writes nothing automatically. Excel export writes one row per category membership in document and membership order, repeating document metadata as needed; unassigned documents retain one row with blank category fields. It preselects a complete `Documents\carrot-results-YYYYMMDD-HHMMSS.xlsx` path that Enter accepts immediately; the path remains editable and falls back to the current directory when Documents is unavailable. Quoted or unquoted `.xlsx` destinations require an existing parent directory. Export confirms before overwrite, writes atomically, and retains the result after success or failure. It creates no JSON sidecar or log. Carrot2 generally works best with roughly 100–1,000 concise documents, but the CLI does not enforce or split on that guidance. Start Over and Back require confirmation before discarding the in-memory batch.

`carrot-cli help` displays Getting Started. `carrot-cli help <topic>` accepts case-insensitive canonical keys and aliases, including spaces or underscores normalized to hyphens. In an interactive terminal, help that exceeds the available height is divided at Markdown block boundaries; use Next Page, Previous Page, Close Help, or Escape. Short topics render immediately, and redirected output emits the complete topic without prompts. An unknown topic prints the canonical topic list and exits with code `1`. Help content is authored under `src/Carrot.Cli/Docs` and embedded in the executable assembly.

The planned named `process` command accepts `--input`, `--endpoint`, `--output`, `--recursive`, `--algorithm`, `--language`, `--template`, `--parameters-file`, `--timeout-seconds`, `--overwrite`, `--no-json-artifacts`, `--quiet`, and `--log-file`. `--quiet` suppresses normal progress and summaries, never warnings or errors, and never suppresses an explicit file log. `--log-file` requires an existing parent directory and appends safe UTF-8 lifecycle, warning/error, exit-code, and artifact-path diagnostics; it excludes content, payloads, credentials, and stack traces. Implemented `preview` uses `--input`, `--endpoint`, `--output`, `--recursive`, `--algorithm`, `--language`, `--template`, `--parameters-file`, `--timeout-seconds`, and `--overwrite`; it validates through `/list`, atomically writes one complete request JSON artifact, and never calls `/cluster`. Without `--output`, it writes `<input-parent>\<input-name>.request.json`; an existing output directory receives that name, and an explicit output file is used as supplied. `server-info` calls only `/list`, displays algorithms, languages, and template names, and never prompts. Process remains deferred.

When no template is selected, algorithm and language default to `Lingo` and `English`; explicit values are matched case-sensitively as an advertised compatible pair. `--template` is matched exactly, is mutually exclusive with `--algorithm` and `--language`, is sent through the `/cluster?template=` query, and omits algorithm/language from the JSON body so the server template supplies them. `--parameters-file` may accompany either selection form and must identify an existing `.json` file no larger than 1,048,576 bytes containing valid UTF-8 JSON with one object root and unique property names. Nested arrays, objects, strings, numbers, Booleans, and nulls are preserved without a client-side algorithm schema. Noninteractive endpoint precedence is `--endpoint`, then `CARROTCLI_ENDPOINT`; a missing endpoint is a configuration error. `server-info` returns `0`, `1`, `4`, or `130` for success, configuration failure, endpoint failure, or cancellation. Noninteractive commands never prompt.

Help topics are getting started, process, preview, server information, iSearch, commands/options, supported formats, extraction rules, clustering settings, output columns, Task Scheduler, exit codes, privacy, and troubleshooting.

Exit codes are: `0` success, `1` invalid command/configuration, `2` partial file-level success, `3` input/no processable documents, `4` endpoint or `/list` failure, `5` `/cluster` or response-contract failure, `6` report/artifact failure, and `130` cancellation. Preview uses `0` for complete JSON output, `2` when file-level extraction failures accompany usable output, `3` when no document is ready, `4` for `/list` failure, `6` for artifact persistence failure, and `130` for cancellation.
